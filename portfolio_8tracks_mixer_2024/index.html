Audio data engineering and applied ML on AWS

Developed AWS software and prototypes to analyse audio files, extract musical characteristics and classify genres. Designed how those results could support music search and recommendations.

Client / context
8tracks.com / mixer.fm
Period
April – August 2024
My role
Data Architect / Head of AI
150–160 TB
audio collection in the project scope
AWS
processing and delivery components
400

Key contribution

Built audio-processing components on AWS, automated their deployment, and developed Python prototypes for feature extraction and genre classification. Proposed a recommendation system combining audio characteristics, listening behaviour and user feedback.

Cloud processing foundation

Developed ML/ETL components for an existing audio collection of approximately 150–160 TB, connecting S3 audio files with metadata and Python feature extraction.

Configured Lambda functions with EFS and RDS proxy access. Worked through service connectivity, VPC/subnet boundaries and the relationship between S3 storage, processing and OpenSearch.

Prepared automated builds with CodeBuild and defined application/infrastructure resources through AWS SAM and CloudFormation.

Feature extraction prototype

Built a local prototype with Essentia MusicExtractor. Converted NumPy outputs into JSON-compatible records, handled missing values and organised danceability, energy, mood, rhythm, loudness, spectral and tonal characteristics.

Processed a demonstration set of up to five M4A files, temporarily staged JSON and batch-loaded results into PostgreSQL. Added measurements of execution duration, CPU, RSS/VMS memory and disk activity using psutil.

Genre classification prototype

Loaded mono audio at 16 kHz and generated embeddings using TensorflowPredictEffnetDiscogs with the Discogs EfficientNet model. Applied the associated 400-genre/style classifier.

Stored filenames, classifications and probabilities in PostgreSQL for a five-file demonstration. Explored how audio features could enrich track metadata and subsequent search/recommendation tasks.

Recommendation architecture and planned extensions

The separate design work considered hybrid recommendations combining collaborative filtering, audio/content features, user feedback and contextual signals. It addressed cold start, sparse interactions, candidate generation and the influence of recent listening.

Specified potential flows for batch feature generation, model training, incremental updates, feedback and API delivery. Evaluated relational storage, object storage, interaction/state stores, analytical history and search indexes for their different responsibilities.

Proposed a development roadmap covering checkpointing, retries, deduplication research, operational dashboards and evaluation through ranking and engagement metrics.

Practical architectural contribution

Translated the music-recommendation concept into distinct responsibilities for data collection, feature processing, model execution, serving, feedback and evaluation. Combined cloud implementation with prototypes to explore how audio analysis could support search and recommendations.
