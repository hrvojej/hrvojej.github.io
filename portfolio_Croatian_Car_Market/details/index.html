Vehicle-market analytics and car-price prediction

Developed vehicle-advertising data collection, market analytics and a car-price prediction model for Oglasnik.hr. The work also included an independent market-data platform that regularly collected and refreshed vehicle listings from Croatian advertising websites.

Business problem and my responsibility

Vehicle advertisements distribute useful market information across many pages and use different formats for price, mileage, engine characteristics and equipment. Comparing vehicles or estimating a price first required turning those pages into usable records.

Led the data engineering and development work: collection, parsing, cleaning, PostgreSQL storage, analysis and predictive modelling. For Oglasnik.hr, developed the car-price estimation model and web components for serving and demonstrating it.

Collecting advertisements from different sources

Built source-specific Python collectors for category pages and individual advertisements. The collectors extracted the advertisement identifier, source URL, publication time, location, price and vehicle attributes, retaining the connection between each record and its original advertisement.

The collection platform included implementations for Njuškalo, Index, Oglasnik and Neostar. Separate parsers handled the different page structures, while saved HTML allowed detailed extraction to be separated from page retrieval.

  • Discover advertisements through category pages and their links.
  • Retrieve the detail pages needed for vehicle specifications and equipment.
  • Convert extracted information into pandas DataFrames for cleaning and storage.

Incremental updates and price-change history

Compared newly discovered advertisement IDs with records already stored in PostgreSQL. Removed duplicate IDs and selected new advertisements for full retrieval, avoiding an unnecessary repeat of the same detailed collection.

For existing advertisements, compared the current advertised price with the stored value. The update logic changed the current-price record and appended the old and new values to a separate history table, making price changes available for later analysis.

Cleaning and preparing vehicle records

Normalized numeric fields such as mileage, production year, engine power, engine capacity, number of gears, doors and price. Removed units and formatting characters and converted valid values to numeric types suitable for filtering, comparison and modelling.

Joined the information from category pages with detailed vehicle attributes by advertisement ID. Source identifiers and retrieval timestamps helped retain the context of each record, while source-specific PostgreSQL schemas kept the collected datasets organised.

  • Vehicle description: make, model, type, production year and model year.
  • Technical attributes: fuel, engine capacity, power, gearbox and consumption.
  • Market context: advertised price, location, publication time, mileage and condition.
  • Additional details: equipment, images and descriptive text when present in the source.

Market analytics in Tableau and Power BI

Created Tableau and Power BI analysis of the collected vehicle data. The Tableau work included views of price, geography, mileage, production year, engine power, fuel, gearbox, condition, publication time and advertisement views.

Combined those views into dashboards so the same market could be examined through vehicle characteristics and location. Used Python visualisation libraries for additional exploration and to prepare the data for modelling.

Car-price prediction and web access

Selected the training dataset and developed an XGBoost model for estimating car prices. The feature preparation considered the vehicle make and model, type, age, mileage, condition, engine characteristics, fuel and gearbox.

Implemented web components for serving the model and demonstrating the predicted result. The development included Python, Flask, jQuery and React components, connecting the analytical work to a usable price-estimation application.

Airflow orchestration and operational tasks

Organised collection into Airflow DAGs with explicit dependencies between category retrieval, advertisement discovery, detail retrieval and database loading. Each source had its own schedule and processing sequence.

Configured run limits, timeouts and email notifications around the recurring jobs. Added supporting tasks for exchange-rate data and scheduler-log maintenance. These operational tasks supported repeatable collection alongside the analysis and modelling work.

Result and relevance

The work connected web collection, a PostgreSQL analytical store, BI reporting and a predictive model. It provided a practical basis for examining the Croatian used-car market and a car-price estimation capability for a classifieds publisher.

The same work demonstrates the ability to take an unstructured external-data problem through engineering and analysis to a business-facing application.
