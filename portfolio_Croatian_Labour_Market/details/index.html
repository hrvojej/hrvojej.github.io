Project in depth

Multi-agency data pipelines for labour-market analytics

Built the collection and preparation jobs used to combine data from Croatian ministries and agencies for labour-market analytics. The work brought different delivery formats into scheduled Python and SQL processing and a shared analytical warehouse.

Client / context
Croatian Ministry of Labour, Pension System, Family and Social Policy
Period
During the Algebra / Algebra LAB engagement
My role
Lead Data Engineer / Developer

In this detail

  1. Collecting data from different institutions
  2. Cleaning and restructuring the inputs
  3. Scheduled warehouse processing
  4. Contribution to labour-market analytics
  5. Source acquisition and the processing layers
  6. Relational processing and portal contribution
← Project overview

Collecting data from different institutions

Worked with ministries and agencies that supplied records in different ways. Implemented acquisition through REST APIs, including the GSD interface, as well as downloaded files, database exports, CSV extracts and SFTP deliveries.

Handled JSON and file-based inputs within the same broader integration effort, with processing adapted to the structure of each source.

Cleaning and restructuring the inputs

Developed Python and SQL procedures to clean and restructure the received records. Mapped each source format into the import, staging and warehouse structures used by the analytical platform.

Combined application-level preparation with SQL procedures for subsequent database processing.

Scheduled warehouse processing

Prepared ETL jobs and execution schedules for loading the analytical warehouse. Worked with Microsoft SQL Server and Oracle in the import, staging and warehouse environment.

The integration work connected repeated source deliveries with the structures required for an ongoing analytical service.

Contribution to labour-market analytics

Prepared integrated data for a unified view of the Croatian labour market. The contribution centred on obtaining the institutional data and making it usable by the portal and its analytical warehouse.

Source acquisition and the processing layers

Different institutions delivered data through different channels. The implementation therefore combined source-specific acquisition with a common progression towards the warehouse.

StageImplemented work
AcquisitionGSD REST/API responses, JSON, downloaded files, CSV/database exports and SFTP deliveries
ImportBring each received source into the platform’s initial data structures
StagingPython and SQL cleaning, restructuring and preparation for integration
WarehouseSQL procedures and ETL loads into the analytical structures

Relational processing and portal contribution

Worked with Microsoft SQL Server and Oracle across the import, staging and warehouse environment. Python handled the acquisition and source-format work, with SQL procedures supporting the database transformations.

The resulting data flows supported a unified national labour-market portal. The contribution was the engineering needed to obtain institutional records and prepare them for a common analytical view; the separate occupational-register applications are described in their own project reference.
