Desktop property-ad analysis and notifications

Developed a desktop application for collecting, analysing and monitoring real-estate advertisements in one place. The application turned property listings into a filterable table and let users define notification rules for new advertisements matching their criteria.

A practical desktop tool for property searches

The aim was to make a property search easier to analyse than a sequence of web pages. A user could load a selected search, inspect listings as structured records and narrow the results using the fields that mattered to them.

Developed the Python application, listing parsers, pandas data preparation, Qt interface and notification rules. Njuškalo property listings were the completed core integration.

Turning listing pages into structured information

Parsed regular and promoted advertisements separately and extracted the identifier, title, property type, floor area, location, price, publication time and source URL. Normalized prices and floor-area values so they could be compared numerically.

Preserved the original advertisement link and publication time alongside the analytical fields. The table therefore supported both comparison and returning to the original listing for further detail.

Interactive tables and filters in PyQt

Built the original desktop interface with PyQt5 and a pandas-backed Qt table model. Column headings, formatted numeric values and clearly displayed links made the collected information easier to read.

Added column selection, text filtering and dropdowns of distinct values using Qt proxy models. Users could filter by location or description, set numeric ranges such as price and floor area, and restrict results by publication time.

  • Review property advertisements in a single table.
  • Combine text and numeric criteria for a more focused search.
  • Open a source advertisement directly from its URL.
  • Export collected records for further analysis.

Configurable monitoring and notifications

Implemented rules with a user-selected checking interval and duration. At each interval, the application refreshed the relevant data, applied the selected conditions and prepared an email table when matching advertisements were available.

Used Qt worker tasks, signals and a thread pool for background work. The interface included start/stop controls, progress information and a countdown to the next check.

Later desktop development

Updated a later application version from PyQt5 to PyQt6 and added an embedded Qt WebEngine browser. The browser could load the selected page, pass its rendered HTML to the parser and then populate the analysis table.

Continued work on table filtering and user feedback for unavailable or invalid pages. This kept the browser view and the structured analysis within the same desktop workflow.

Separate work on a common listing model

Developed a separate Python prototype that mapped saved listing records from different provider formats into a common property model. Its SQLite repository stored advertisements and recorded changes in price.

This prototype explored how a wider property-data system could normalise records across providers. It was a separate development component from the completed desktop integration.

Result

Produced a Windows desktop application that combined collection, tabular analysis, filtering and notifications for property searches. The project brought Python data processing into a tool usable directly from a desktop computer.
