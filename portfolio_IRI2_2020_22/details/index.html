Project in depth

Phasor-angle comparison and PLC control for grid regulation

Developed real-time software for grid regulation: comparing phasor angles measured at different grid locations, performing power-system calculations and triggering PLC actions. The project achieved a response below 50 ms, significantly faster than SCADA in this project. Python and Java/Kafka Streams connected the electrical measurements, calculations and control decisions.

The grid-control problem and my contribution

A useful control decision depends on comparing electrical measurements from the same moment. The application had to receive measurements from two PMUs, match corresponding readings, calculate the differences and act when a rule was exceeded.

My work covered the PMU applications, measurement preparation, Java stream processing, phasor-angle calculations and connection of the rule results to PLC triggering. The wider project involved distributed generation, storage and charging infrastructure.

Comparing voltage phasors across all three phases

Implemented separate comparisons for the R, S and T voltage phases. For each phase, the application extracted the angles reported by the two PMUs, converted the polar angles from radians to degrees and calculated their difference.

Normalised each difference around the half-turn boundary so that values close to opposite ends of the angle scale could be compared consistently. Each phase then had its own threshold check based on the magnitude of the difference.

Published the calculated differences together with the associated source values and timestamp. This kept the electrical result connected to the measurements used to calculate it.

Turning a rule result into a PLC action

Connected the phase-angle checks to a Java PLC trigger through an S7 connector integration. Exceeding a phase threshold invoked the control action directly from the rule-processing application.

The control function was driven by the electrical calculation. The Kafka output also retained the calculation result for inspection and storage.

Matching PMU readings before calculation

Small differences in the last decimal places of timestamps could prevent strict equality from pairing measurements that belonged together. The producers therefore retained the original timestamp and prepared a rounded matching key.

Developed a separate Kafka Streams application that joined the two measurement streams. It used rounded measurement timestamps as keys and a short join window to pair corresponding readings.

The joined record preserved the source timestamps, device identifiers, sequence counters, voltage and current phasors, frequency, rate of change of frequency and analogue/digital fields. This gave the calculation application the measurements from both locations in one typed record.

Keeping the join and the electrical rules in separate applications made their responsibilities clear: one matched the readings; the other calculated and applied the grid-control conditions.

Python PMU applications and typed measurement records

Built Python producers around the C37.118 synchrophasor/PDC interface. They requested measurements, decoded the received measurement frames through the protocol library and mapped the relevant values into explicit records.

Preserved the original measurement timestamp and added a rounded timestamp for matching. Serialised the records with Avro and Schema Registry so that the Python producers and Java applications agreed on field names and types.

Worked through protocol-level reception and decoding issues with real PMU hardware, including comparison of captured network traffic with simulator behaviour.

Result and relevance

Achieved a grid-control response below 50 ms, significantly faster than SCADA in this project. PMUs supplied fresh measurements every 20 ms.

The work combined data engineering with electrical-domain calculations and PLC control. It required understanding what the measurements meant, matching them correctly and using the calculated result to produce the required equipment response.

Diagnosing real-device communication

Worked with command, configuration and data frames of the C37.118 protocol. The Python application received binary messages through TCP sockets, assembled the packets and used the protocol library to produce structured measurements.

Investigated a pyPMU problem where the simulator and tinyPDC example worked but the real PMU stream failed after a valid configuration frame. Compared network captures and Wireshark/PCAP evidence with the application behaviour to identify and resolve the reception/decoding issue.

This work was integration and diagnosis around an existing protocol library, alongside the project’s own producers and measurement mapping.

Operating the complete installation

Prepared Kafka Connect sinks and PostgreSQL tables for raw measurements, joined records and calculated results. SQL processing made the results available in tabular form for inspection and the wider control application.

Prepared an Ubuntu/Docker Compose environment containing Kafka and its supporting services: ZooKeeper, Schema Registry, Connect, REST Proxy, ksqlDB and Control Center, together with a PostgreSQL container.

Documented the startup sequence: platform and database, connectors, the two PMU producers, the stream-join application, and the electrical-rule/control application. Build procedures covered Java/Gradle packaging and the Python environment.

Operational checks included service logs, topic contents, connector state and database tables. A scheduled retention procedure maintained a short operational history in the raw, joined and result tables.
