What the system did and what I developed

The system compared electrical measurements from different points in the distribution grid and used the results to determine when grid equipment should react. The wider project addressed real-time grid regulation involving distributed generation, energy storage, charging infrastructure and electric vehicles.

Developed software that aligned PMU readings in time, calculated differences between phasor angles, performed other power-system calculations and triggered PLC actions based on the results. Python, Java and Kafka Streams supported these calculations and control functions.

Grid-control response below 50 ms

Compared phasor angles from synchronised PMU measurements and implemented additional power-system calculations used to regulate the grid. In this project, the solution responded in under 50 ms, significantly faster than SCADA and within the project requirement of less than two seconds.

PMUs supplied fresh measurements every 20 ms. Java/Kafka Streams applications performed the calculations, and a reactive Java application used their results to trigger PLC actions.

PMU ingestion and protocol-level diagnosis

Implemented Python socket applications that received PMU (Phasor Measurement Unit) measurements over TCP. Reassembled binary/hexadecimal message bytes into protocol frames and converted them into structures suitable for downstream processing.

Handled C37.118 command, configuration and data frames. Extracted device identifiers, timestamps, status values, voltage and current phasors, frequency, rate of change of frequency, and analogue/digital values.

Diagnosed and resolved a pyPMU/Python Synchrophasor Module issue that prevented correct ingestion from a real PMU, despite successful simulator and tinyPDC tests. Used captured network traffic and Wireshark/PCAP analysis to investigate the failure between configuration-frame reception and data-frame decoding.

Preparing PMU measurements for calculation

Installed and operated a Kafka platform on an Ubuntu server. The Docker Compose environment included a broker, ZooKeeper, Schema Registry, Kafka Connect, REST Proxy, ksqlDB, Control Center and a separate PostgreSQL container.

Developed independent Python producers for two PMU inputs. Transformed protocol frames into Python dictionaries, serialised them with Avro, and maintained consistent types through Java stream-processing objects and PostgreSQL destination tables.

Preserved original timestamps and introduced a rounded timestamp for synchronisation. Included source/device identifiers and the values required to trace message sequences and reproduce calculations.

Synchronising PMU readings and calculating grid-control values

Built a Java application with the Kafka Streams API to join the two PMU streams. Small differences in the least-significant timestamp digits could otherwise cause matching measurements to be missed; the rounded timestamp served as the join key.

Published the synchronised measurements to a separate stream. A second Java/Kafka Streams application calculated phasor-angle differences and other electrical quantities needed for grid regulation. Stream synchronisation and power-system calculations ran as separate applications.

From calculation results to PLC control

Created Kafka Connect sinks for raw measurements, joined streams and calculated results. Maintained compatibility between Avro schemas, data types and PostgreSQL tables.

Developed SQL triggers to process and expose stream-processing results in tabular form with low delay. A separate reactive Java application connected rule outputs to PLC triggering for network equipment.

The purpose was to turn the electrical calculations into the required PLC reaction for grid regulation.

Deployment, monitoring and maintenance

Prepared an ordered startup procedure covering the platform, database, connectors, producers, join application and rule application. The development environment used Python virtual environments, Java, Gradle builds and separate tmux sessions.

Documented checks for Docker services and logs, Kafka topics and live records, connector states and configurations, and database contents, sizes and permissions. Added an hourly cron retention procedure for raw, joined and result tables.

Research direction

Investigated Spark analytics and predictive ML as potential extensions for analysis of the collected energy data.
