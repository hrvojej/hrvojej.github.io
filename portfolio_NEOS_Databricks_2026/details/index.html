Project in depth

Databricks engineering: workshops, labs and team enablement

Designed and delivered a two-day Azure Databricks workshop for NEOS, part of KONČAR Group, and developed a wider set of practical learning materials. The programme connected data-engineering concepts with runnable labs, banking examples and follow-up engineering assignments.

Client / context
NEOS (KONČAR Group)
Period
20–21 April 2026 · follow-up learning materials
My role
Workshop Author / Data Engineering Instructor

Preparing an environment the team could use

Adapted the material to the team’s workspace, available permissions and compute setup. Prepared Azure setup guidance and practical checks for storage, workspace access and the tools needed by participants.

Organised the material around Associate and Professional topics, with guided exercises for the live workshop and deeper examples for later study.

Delta Lake and incremental ingestion

Built exercises around Delta transactions, history, time travel, restore, MERGE and Change Data Feed. Explained the consequences of retention and VACUUM through concrete table operations.

Prepared Auto Loader exercises with file ingestion, checkpoints, schema inference and evolution. Demonstrations covered changes in incoming structures and how to inspect processing progress and problematic records.

Transformations, modelling and streaming

Developed SQL and PySpark labs covering window functions, joins, arrays and nested structures, user-defined functions and Medallion modelling. The advanced material addressed Spark query behaviour, performance and dimensional modelling.

Streaming examples covered checkpoints, triggers, state, event time, watermarks and late records. The learning sequence linked incremental ingestion with transformations and downstream table behaviour.

Data quality and governance

Prepared exercises for constraints, validation, expectations, rejected-record handling and pipeline monitoring. Used examples to show how invalid data can be inspected instead of silently reaching analytical tables.

Unity Catalog material covered catalogues, schemas, volumes, permissions and access control. The wider curriculum included handling sensitive data and separating responsibilities across engineering and administration.

Banking lakehouse and dbt demonstration

Built a banking demonstration to connect source preparation, layered transformations and analytical outputs. Developed and diagnosed a dbt example, reran the model and test sequence, and used the results to explain verification and repeatable execution.

Prepared follow-up data-engineering tasks with source inputs, expected processing steps and acceptance criteria so participants could practise beyond individual notebooks.

DevOps and platform-engineering learning package

Created a separate practical package covering local tooling, Databricks CLI, Git, authentication, workspace inventory and permissions. Included Bundles, target configuration, validate/deploy/run steps and a small demonstration workload.

Extended the learning path to GitHub Actions, promotion between environments, release notes, rollback, monitoring and incident diagnosis. Distinguished exercises participants could run with their own permissions from administrator-level topics.

Teaching approach and reusable material

Combined explanations, demonstrations, guided labs, independent assignments and evidence of execution. Connected tasks with certification topics while keeping the focus on understanding how the platform behaves.

Published a browsable workshop site so that the team could revisit the examples and use the material after the workshop.
