Teaching format and adaptation to the team

The core workshop ran over two full days, approximately eight hours per day, with a planned group of ten data engineers. Material combined conceptual explanations, code demonstrations, guided labs, independent application and discussion of solutions.

Mapped topics to Databricks Data Engineer Associate and Professional certification areas. Adapted the schedule to the team’s platform and available time. More involved local PostgreSQL/simulator setup was moved into follow-up assignments.

Used an Azure Databricks Premium environment supplied by the platform team. Defined practical responsibilities for instructors and learners alongside infrastructure, IAM and administrator tasks, with extended exercises provided as follow-up material.

Core engineering curriculum

  • Delta Lake: tables, ACID behaviour, history/time travel, MERGE, Change Data Feed, OPTIMIZE, Z-ORDER, VACUUM, query profiles, Liquid Clustering and Deletion Vectors.
  • Auto Loader: incremental file ingestion, schema discovery, persistence and evolution, malformed-record handling and Bronze-layer responsibilities.
  • SQL and modelling: windows, complex types, higher-order functions, joins, UDF trade-offs, Spark/AQE, dimensional modelling and Bronze/Silver/Gold transformations.
  • Streaming and changes: Structured Streaming, state, watermarks, CDC/application of changes, Change Data Feed and reliable recovery.
  • Data quality and privacy: constraints, expectations, quarantine, event-log analysis, PII and compliance-oriented learning scenarios.
  • Orchestration and delivery: task dependencies, retries, task values, conditional branches, Jobs/Workflows, Bundles and multiple environments.
  • Governance: Unity Catalog, groups/grants, row filters, column masking, anonymisation, lineage, Delta Sharing, federation and audit system tables.

Banking lakehouse and dbt demonstrations

Built synthetic banking demonstrations from data generation and ingestion to transformations, suspicious-event detection, validation and case queues. Prepared instructor learning paths and validation notes so outputs could be interpreted as well as executed.

A separate dbt banking workflow combined models/tests, an execution-summary task, conditional continuation and a case queue. Diagnosed a TABLE_OR_VIEW_NOT_FOUND failure caused by duplicated schema naming and corrected the generate_schema_name macro.

Validated the synthetic-data banking demonstration with a successful dbt run: 29 passing tests, zero warnings and zero errors.

Self-paced Data Engineering assignment

Created a sequenced set of setup guides and implementation tasks, including an offline website and local launch scripts. A banking simulator used four PostgreSQL domains: customers/accounts, cards/transactions, loans/repayments and operational fees/interest/end-of-day processing.

Prepared partially synthetic data with deterministic seeds and preserved primary/foreign-key relationships. Defined three snapshots with approximately 5% changed and 10% new records to exercise incremental processing. Exported to Parquet and uploaded through the Databricks SDK.

The assignment progressed from Auto Loader Bronze ingestion to Silver MERGE/SCD2 and Gold marts. It included quality criteria, workflow orchestration and an optional streaming fraud/AML exercise.

Submission expectations included meaningful commits, a reproducible README, certification-topic mapping and evidence that acceptance criteria were met. Instructor review and feedback could be handled through issues and pull requests.

DevOps and Platform Engineering package

Developed 23 guides and a Croatian offline learning site. Explicitly separated business-logic ownership, deployment ownership, infrastructure administration and security/IAM responsibilities.

The package covered local tools, CLI authentication, Git/PR practice, platform inventory, Bundles, VS Code/YAML, secret handling, U2M/M2M/OIDC, service principals, least privilege, compute policies and cost controls.

Delivery exercises covered validate/deploy/run, run identifiers, smoke checks, GitHub Actions, DEV/TEST/UAT/PROD promotion, release notes, rollback and incident diagnosis. dbt integration included profile separation, target mapping and debug/parse/build stages.

Advanced administrator topics such as SCIM, private connectivity and account audit were kept separate from learner-level execution. The demonstration workload and grading rubric tied concepts to observable evidence.

Technical mentoring and knowledge transfer

Connected architecture concepts to working examples spanning ingestion, transformation, governance and delivery. Used labs and review criteria to help engineers interpret outputs, diagnose failures and understand ownership across teams.

Provided follow-up learning paths and reproducible exercises for continued practice, including Data Engineering and DevOps / Platform Engineering assignments.
