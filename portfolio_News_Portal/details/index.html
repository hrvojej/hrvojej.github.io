Project in depth

News collection, AI summaries and web publishing

Built an independent news portal covering collection, data storage, AI-assisted summarisation and web publishing. Developed the project using Oracle Cloud, with a Python and PostgreSQL backend and generated pages for browsing articles and categories.

From source articles to a readable portal

Developed the collection and publishing workflow as well as the data model and article pages. The system gathered article information from multiple publishers, enriched it with structured summaries and organised the results into a browsable website.

The implementation separated collecting source material, preparing its analytical fields and publishing the reading experience. This made each stage easier to change without rewriting the whole portal.

Source-specific collection with shared components

Built RSS and HTML collection modules for ABC, Al Jazeera, BBC, Fox, The Guardian, The New York Times, Reuters and CNN. Shared parser components handled requests, XML parsing, database sessions and common error reporting; source-specific components handled each publisher’s fields and page structures.

Preserved article URLs, categories, publication times, descriptions and image references. Normalized publication timestamps and used the article URL as a unique key so repeated collection could update existing records.

  • Discover source categories and feeds.
  • Collect article records and update changed entries.
  • Retrieve article content through the relevant source parser.
  • Record fetch and parsing status for subsequent processing.

PostgreSQL model and controlled schema changes

Designed a registry of news sources and separate category, article and processing-status models. Source-specific schemas followed a shared structure, with URL uniqueness, category relationships and publication-time indexes.

Used SQLAlchemy for database access and Alembic migrations for schema changes. Stored structured summary fields in JSON/JSONB alongside the original article context, allowing the same analysis to be used by the database and the page templates.

Dagster orchestration and repeatable processing

Created Dagster jobs that sequenced category discovery, article discovery and content updates. Staggered source schedules spread recurring collection across different minutes rather than starting every source together.

Added a separate job chain for summarising articles, generating category pages and publishing the site. Logs and processing-status records made failures visible and identified the articles still requiring work.

Implemented database row claiming for pending summarisation and backfill routines for missing structured fields. These mechanisms supported controlled batch processing and reprocessing.

Structured AI summaries

Implemented a two-stage LLM process: first create a plan for an article summary, then generate its sections. Parsed and normalized the returned JSON into consistent fields for the title, keywords, entity groups, main points, additional details and related resources.

Kept model access behind a configurable integration layer and connected the structured result to database storage and HTML templates. The work used existing language models for inference and focused on orchestration, output structure and application integration.

Article, category and homepage generation

Built Jinja templates for article pages, category pages and the homepage. Generated navigation links and category groupings, retained source attribution and added related-article links from the stored data.

Implemented keyword-based image lookup and image preparation for the page layouts. Generated consistent filenames and relative links so articles in different category folders could share navigation and static assets.

Cloud publishing

Used Oracle Cloud during development of the project. The publishing implementation also included generated static files in Cloudflare R2, a Cloudflare Worker for serving them and a scripted update process.

The Worker handled redirects, HTML fallbacks, content types and the missing-page response. It applied different cache settings to frequently updated HTML and longer-lived images, stylesheets and JavaScript.

Optional analysis of online reactions

Developed an optional extension for collecting topic-related online comments and generating summaries of the reactions around people, institutions and events mentioned in an article.

Kept this analysis separate from the main article summary and allowed collection failures to leave the main publishing process intact. Its outputs were exploratory model-generated summaries of the collected reactions.

Result and relevance

Built the components of a news portal from external-data collection through database design and AI-assisted processing to the published page structure. The project demonstrates integration of data engineering, applied AI and web delivery in one system.
