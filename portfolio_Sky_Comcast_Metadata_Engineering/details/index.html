Project in depth

Turning Confluence documentation into structured metadata

Led the extraction and modelling of Sky / Comcast’s Confluence data-model documentation into a PostgreSQL metadata repository. Built separate processing for table descriptions, column definitions, business metadata, governance information and source-to-target mappings, with consolidated views and spreadsheet exports.

Client / context
Comcast / Sky Group / Sky UK · via Intuita Consulting
Period
During the Intuita engagement · September 2022 – February 2024

Lead Engineer / Developer

The problem: useful metadata embedded in documentation

The Customer Spine data-model documentation combined page hierarchies, explanatory text and tables. The information needed for governance and technical analysis was present, but it could not be treated as one uniform spreadsheet.

I first analysed the structure and meaning of the pages, then developed Python extraction and SQL modelling for the different types of information. This separated the task of retrieving a page from understanding what each section of that page represented.

Preserving the documentation hierarchy

The documented extraction covered eight top-level pages across five spine levels and 166 second-level pages. I created a relational representation of the links between the levels so that lower-level column descriptions could be enriched with the corresponding higher-level context.

A page-structure extraction step populated the relationship table before the downstream metadata views were assembled. Preserving those parent-child relationships prevented a column description from losing the source-system or model context in which it was documented.

Rendering and retaining the source pages

Used Selenium with the authenticated Chrome environment to retrieve fully rendered Confluence pages. This mattered because some information was held in JavaScript-rendered tables.

Separated page retrieval from subsequent parsing. Downloaded HTML was retained in distinct table, level-one and level-two collections, so extraction rules could be refined without retrieving every page again.

The engineering environment used Python, pandas, BeautifulSoup/lxml-related parsing libraries, PostgreSQL and psycopg2. The delivery instructions documented the environment and how to run the individual scripts.

Dedicated table-level extraction

Built a sequence that retrieved table-description pages, loaded the initial source-table metadata and extracted the Business Metadata and Governance Metadata sections separately.

The final table view joined those results into a consolidated representation. Separating the source information into relational tables made it possible to reuse the extracted content in different views and exports.

Column-level extraction and mapping logic

Developed distinct extraction steps for the different sections of second-level pages, rather than flattening all prose into one text field.

Relational outputs, views and exports

Stored extracted information and page relationships in PostgreSQL. Built separate consolidated views for table and column metadata, then exported those views to CSV and Excel.

The outputs could be queried and combined through SQL instead of remaining dependent on manual navigation through Confluence. The project also involved Collibra in the wider metadata-governance context.

The delivery documentation maps each script to its input collection and output table or view. This provides a concrete handover route: retrieve pages, extract each metadata category, assemble views and generate the required export.

Delivery and reuse across the organisation

Delivered the Python processing, relational model, consolidated views, exports and operating instructions. Presented the work to the Sky Italy team; the professional project record notes their subsequent adoption of a similar approach.

The contribution was the conversion of complex documentation into structured, reusable metadata while retaining its relationships and business context.
