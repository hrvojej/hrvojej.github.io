A national platform with six connected modules

Worked for Agency for Commercial Activities (AKD) and the Croatian Ministry of the Sea, Transport and Infrastructure from November 2025 to August 2026 on the EU-funded C1.4.R1-I5 project. The scope joined transport monitoring, training and examinations, electronic permits, integrations, user/role administration and reporting.

My role connected solution and data architecture with detailed specifications, implementation coordination and validation. It included API architecture and UAT leadership, together with a distinct unified-analytics design assignment.

The Agency for Commercial Activities is AKD (Agencija za komercijalnu djelatnost), the Croatian company providing digital identity, secure-document and public-sector digital services.

Solution architecture and shared business facts

Defined architectural views for the modules, common domain concepts and responsibility boundaries. The same organisations, people, vehicles, permissions and operational facts needed consistent meaning as a process crossed module boundaries.

Specified service boundaries, data ownership, access rules and audit requirements. Connected architectural decisions with development tasks, interface specifications and the evidence needed for acceptance.

From business process to development specification

Prepared process descriptions, use cases, business rules, state models, screen catalogues, logical data models, SQL foundations, API requirements and test scenarios. The aim was to make the expected behaviour sufficiently explicit for developers, testers and business stakeholders to assess the same thing.

Documented the role responsible for an action, required inputs, allowed state changes, exceptions and what a later step should see. Updated the specifications after workshops, legal clarification, interface confirmation and UAT findings.

Maintained traceability between a requirement, its implementation task, the expected application behaviour and the check used to accept it.

Data architecture for the AFFINIS analytics expansion

Authored a separate technical design for bringing eADR and eFTI/NSCP data into the existing AFFINIS lakehouse and connecting them with Taho/SOTAH analytics. The scope covers ingestion, source-code harmonisation, shared entities, dimensional models, processing, reporting and source-to-report checks.

Delivered the analytical design baseline, focused validation requirements and infrastructure-upgrade assessment. The separate unified-analytics case provides the architecture and documentation detail.

Local RAG knowledge base for architecture and development specifications

Built and used a local retrieval layer for RAG workflows over the project knowledge base and current development specifications. It supplied relevant source passages for AI-assisted work with requirements and architecture, with a document and section reference for checking the original context.

The saved August 2026 index contained 200 documents: 57 knowledge-base documents and 143 development-specification documents, divided into 16,773 text chunks. The stored embedding matrix had one 384-dimensional vector per chunk.

Combined semantic similarity from local FastEmbed embeddings with BM25 keyword relevance and document recency. The stored index used a multilingual MiniLM embedding model. Search results included source references, section headings, document dates and component scores.

Exposed search, targeted document reading, index status and rebuilding through Model Context Protocol (MCP) tools and a command-line interface. The purpose was to retrieve the relevant specification passages for project work while retaining a route back to the original documents.

  • Discovered the knowledge-base documents and current development specifications from their catalogue; excluded archive and backup directories.
  • Split Markdown by headings and paragraphs, then created overlapping chunks to retain neighbouring context.
  • Stored source and section references with each chunk, together with dates used to distinguish current material from older context.
  • Persisted the document inventory, chunks and embeddings locally; detected changes in file membership, modification time and size to identify a stale index.
  • Implemented source-discovery tests covering current module specifications, consolidated specifications and exclusion of archived copies.

Identity, organisation and permissions

Separated authentication from a user’s organisational context and local permissions. Defined a common role-based access approach rather than allowing each module to interpret access independently.

During validation, checked actual NIAS user contexts, organisations, roles and permission scope. Positive checks established that permitted actions worked; negative checks examined whether access outside the intended scope was prevented.

The work covered human and technical identities, administration and audit. Cross-module checks verified that permissions and business state remained consistent when a process moved to the next step.

API behaviour and unresolved external dependencies

Specified API contracts, versioning, input validation, idempotency, retries, errors, audit and security requirements. Defined the ownership of vehicle, driver, permit, transport-plan, route, organisation and inspection information.

Prepared mock/test approaches so development could progress before every external service was confirmed. Tracked outstanding protocol, endpoint, access and data-freshness decisions separately from implemented application behaviour.

This made integration readiness an explicit delivery condition. A prepared interface specification and a fully accepted live integration were treated as different milestones.

Regulatory interpretation and stakeholder coordination

Mapped ADR, the eFTI regulation, dangerous-goods transport requirements, NIS2-related requirements and national rules into processes, functional specifications and acceptance criteria.

Coordinated material and decisions with Agency for Commercial Activities (AKD), Croatian Ministry of the Sea, Transport and Infrastructure (MMPI), Croatian Ministry of the Interior (MUP), Croatian Vehicle Centre (CVH), Croatian Customs Administration, the State Inspectorate of the Republic of Croatia and technical stakeholders. Converted workshop conclusions into concrete specification tasks and traceable decisions.

Maintained decisions, risks, open questions and their owners. Requirements awaiting an authoritative decision remained identifiable rather than silently becoming assumed implementation rules.

Environment and operational requirements

Specified needs for DEV, TEST, DEMO/UAT and production preparation, including network/security zones, monitoring, event logging, backups, recovery and operational ownership.

Connected those requirements with the access and integration checks that needed to be possible in each environment. Defined reporting needs such as filters, drill-down and controlled export in relation to operational data and user roles.

UAT evidence and acceptance across P1–P4

Prepared test plans, checklists and acceptance criteria across all six modules and delivery stages P1–P4. Tested functional behaviour, authentication, permissions, integrations and complete business scenarios in DEMO/UAT environments.

Recorded expected and actual behaviour, screenshots, test-data identifiers, blockers, cleanup and the conditions for repeating a test. Re-read the resulting business information in the following process step to check that a change was actually visible and correct.

Recorded stateMeaning in the validation workflow

PARTIALOnly part of the expected behaviour was confirmed
FAILObserved behaviour did not meet the expected result
BLOCKEDA dependency or environment condition prevented the check

Technical delivery leadership

Established the technical backlog, priorities, delivery sequence and tracking of P1–P4. Coordinated application development, infrastructure, security, integrations and validation using Git, Jira, Confluence and the project knowledge base.

Prepared status reports, readiness assessments, workshops and inputs for Go/No-Go decisions. Escalated access/security defects, integration failures and interrupted business flows, with explicit required fixes and retest conditions.

The delivered contribution was a connected set of architecture and development specifications, integration definitions, delivery coordination and acceptance evidence. It made the distinction between a partially working scenario and one ready for acceptance visible to decision makers.
