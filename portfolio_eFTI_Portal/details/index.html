Project in depth

Freight-data exchange, access control and an eFTI portal

Developed an eFTI portal implementation covering freight datasets, controlled information sharing and a web interface. The work connects a Java backend and React frontend with XML schemas, identity, access-link lifecycle management and audit records.

Application and data architecture

Built the application around Spring Boot, PostgreSQL and Liquibase, with a React and TypeScript interface. Organised the domain into datasets, consignments, attachments, access links, audit and supporting services.

The development stack includes Docker, automated build workflows and separate backend and browser-test tooling.

Frontend and verification tooling

Used React, TypeScript, routing, form validation, query management and internationalisation for the web interface. Integrated OpenID Connect with the identity setup.

Included Vitest, accessibility checks and Playwright end-to-end test tooling.

XML validation and subset selection

Implemented XML validation against the consignment XSD through JAXB, with schema loading from application resources and explicit validation errors. The XML-processing components restrict external DTD/entity handling.

Prepared structured API representations for the common dataset and connected these with the XML exchange format. Included schema resources and API documentation.

The subset service collects allowed element paths from the subset registry, which derives its mappings from XSD annotations. For multiple requested subsets it forms the union of their fields, retains the ancestor elements needed to keep the document structure and removes unrelated branches.

The filtering logic distinguishes a fully included element from one whose children must still be filtered. This is a concrete implementation of subset-based data exchange rather than a manually maintained list of fields in a screen.

Access-link lifecycle

Modelled the association between a dataset, gate and platform as an access link. The service persists link state, activation/deactivation timestamps and audit events.

State / operationImplemented behaviour
CreateCreate an active link for an existing dataset
DeactivateMove an active link to a reversible inactive state
ReactivateRestore a deactivated link to active
RevokeRecord permanent revocation rather than a reversible pause
ExpireDetect an elapsed expiry time during validation and mark the link expired

Binary attachments and integrity metadata

Built upload, list, retrieval and deletion operations for dataset attachments. Upload validation checks empty content, configured file-size and per-dataset limits, and the allowed MIME-type list.

The service checks dataset ownership for upload/deletion, uses a generated storage key and sanitises the supplied filename. It records the file size, media type, creator, creation time and SHA-256 digest alongside the dataset relationship.

Storage handling and attachment metadata are separate components, so the application can retrieve the file without using the original filename as its storage identity.

Retention, audit and operation

Implemented scheduled and administrator-invoked archive processing. The service identifies records past the configured active period, marks them archived and later processes records past the archive-retention period.

Datasets with an active authority-access link are skipped by the retention routine. The run records archived/purged and skipped counts, and writes the associated audit events.

The wider implementation uses Spring Boot, PostgreSQL and Liquibase with a React/TypeScript frontend, OAuth2/OIDC integration and container/CI tooling. Test tooling is part of the development project; the portfolio does not imply formal eFTI certification or an independently certified security assessment.
